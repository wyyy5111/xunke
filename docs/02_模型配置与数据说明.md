# 模型配置与数据说明

本页描述完整后端服务。GitHub Pages 仅展示已有演示数据，不执行模型调用、生成或数据写入。

## 默认离线演示

交付默认配置为 `LLM_PROVIDER=mock`。无需提供密钥即可演示：课程资料解析 → 本地检索 → 学生诊断/路径 → 十 Agent 编排 → 资源生成 → 规则与模型辅助质量评估 → 教师审核发布 → 学习练习/后测报告。

其中课程解析、检索、数据存储、权限和业务状态流转是真实代码执行；MockProvider 的内容生成依赖本地模板，不能据此评估远程大模型的生成质量、推理能力或速度。初始化库中部分 Agent 历史轨迹及测评数据为演示种子；主动启动新任务后会生成新的实际执行记录。

## 真实远程模型配置

源码白名单固定为 `deepseek-v4-flash`，当前接入只支持 `mock` 或 `deepseek`。这描述的是工程内实现，不构成服务商可用性保证；本次没有有效密钥，未发起真实远程推理，也未验证远程模型当前账号授权或效果。

1. 获取本人/团队有权使用的服务商 API Key，并核对模型服务可用性。
2. 桌面版打开菜单“应用 → 打开用户数据目录”，编辑其中 `.env`。源码版复制根目录 `.env.example` 为 `.env` 后编辑。
3. 修改以下配置：

```dotenv
LLM_PROVIDER=deepseek
LLM_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_API_KEY=在本机填写自己的密钥
```

4. 完整退出并重启应用，查看系统模型状态，再启动生成任务，核对 LLM 日志的 provider、模型和状态。

密钥只能保留在本机配置，不应写入源码、报告、视频或提交压缩包。配置无 Key 时有效 Provider 会表现为 Mock。合法配置发生网络或服务错误时，系统可降级为明确标记的 Mock，日志记录调用失败与降级；模型白名单以外的值会被明确拒绝，而不是静默改写。确认真实调用时应同时检查有效 Provider 和具体调用日志。

## 当前能力边界

- 检索：SQLite 持久化课程片段，字符 TF-IDF 与词项重叠混合排序；不是外部 Embedding 或向量数据库。
- Agent：固定职责的十节点后端编排，含规则/数据处理节点与内容生成节点；不是十个独立训练的大模型。
- 多模态：目前生成结构化 PPT 大纲、视频脚本和实验方案等资源，不包含自动拍摄或渲染成片。
- 质量门控：规则评分与模型辅助评分融合（当模型返回有效评分时为 0.55 × 规则分 + 0.45 × 模型分），再由教师人工审核控制发布，用于检查可用性和提示风险，不是事实绝对正确的证明。Mock 模式下模型评分也来自本地模板。
- 教学效果：预置成绩、画像、前后测提升为演示数据；尚需真实课堂用户实验验证。
- 运维：单机 SQLite 与进程内任务调度；未宣称完成分布式扩展或高并发压测。
- 文档：可解析具有文本层的资料，尚未集成扫描件 OCR。

## 演示数据及使用条件

完整服务中的默认账号用于本地评审；Pages 使用同名的公开演示人物，不连接完整服务的身份认证。若部署到共享网络或正式教学环境，应配置随机 JWT_SECRET、限定访问来源、停用/轮换演示账号并处理真实用户数据授权。应用当前使用 localStorage 保存前端 Token，生产安全设计需结合实际部署条件进一步完善。

演示资料、成绩和历史轨迹由程序初始化提供；用户真实上传资料及本地数据库不会随本次压缩包提交。项目未授权统一的公开开源许可证，第三方依赖按其各自许可证使用；比赛提交不等同于授予公众再分发许可。
